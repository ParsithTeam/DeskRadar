# وضعیت اتصال فرانت به بک‌اند

این گزارش فقط موارد مرتبط با فرانت و قرارداد API را پوشش می‌دهد. دیتابیس، AI، چت و بازخورد تحلیل در این فهرست نیستند.

## موارد متصل‌شده

- لیست تیکت‌های کاربر و ادمین با ساختار جدید `items` و `total`
- ثبت تیکت و اجرای دستی تحلیل
- جزئیات جداگانه تیکت برای کاربر و ادمین
- تغییر وضعیت تیکت
- جزئیات رخداد و تغییر وضعیت‌های `confirmed`، `dismissed` و `resolved`
- لیست هشدارها، دریافت زنده، خوانده‌شدن و تخصیص هشدار به اولین ادمین
- لیست، جستجو، جزئیات و ساخت مقاله پایگاه دانش
- تیکت‌های مشابه و مقاله مرتبط در خروجی تحلیل ادمین

## موارد باقی‌مانده

### ۱. خروجی لیست رخدادها ناقص است

خروجی فعلی `GET /incidents` برای هر رخداد فقط این فیلدها را می‌دهد:

```text
title_fa, severity, status, updated_at, resolved
```

فرانت حداقل این فیلدها را نیاز دارد:

```text
id, title_fa, reason_fa, severity, status,
ticket_count, created_at, updated_at
```

مهم‌ترین مورد `id` است؛ بدون آن فرانت نمی‌تواند رخداد را در لیست شناسایی کند یا لینک صفحه جزئیات را بسازد. در وضعیت فعلی صفحه جزئیات رخداد کار می‌کند، اما صفحه لیست رخدادها قابل استفاده نیست.

### ۲. خروجی لیست تیکت‌های ادمین دو فیلد کم دارد

خروجی `GET /api/tickets/admin` این دو فیلد موردنیاز جدول را برنمی‌گرداند:

```text
category
confidence
```

برای لیست، فقط همین مقادیر خلاصه کافی است و نیازی به ارسال کل تحلیل تیکت نیست.

### ۳. فیلترهای لیست تیکت ادمین نتیجه را تغییر نمی‌دهند

پارامترهای زیر در API تعریف شده‌اند، اما در تست واقعی روی نتیجه اثری نداشتند:

```text
q, category, urgency
```

برای مثال درخواست با `category=email` یا یک `q` ناموجود همچنان همه تیکت‌ها را برگرداند.

### ۴. خروجی لیست تیکت‌های کاربر برای UI فعلی کافی نیست

خروجی `GET /api/tickets` فقط اطلاعات خیلی خلاصه را می‌دهد. کارت‌های فعلی فرانت این دو فیلد را نیز نیاز دارند:

```text
description
confidence
```

اگر قرار است لیست عمداً خلاصه بماند، باید نمایش این دو مورد از کارت لیست حذف شود و فقط در جزئیات تیکت نشان داده شود.

### ۵. احراز هویت API ندارد

فرانت همچنان از ورود موقت محلی استفاده می‌کند، چون API لاگین و دریافت کاربر جاری وجود ندارد. همچنین نام کاربر در `current_user` و `requester` از فرانت ارسال می‌شود.

برای اتصال نهایی Auth، بک‌اند باید توکن و اطلاعات زیر را برگرداند:

```text
id, name, email, role
```

## نکته مربوط به شاخه‌ها

در زمان بررسی، شاخه `backend` یک کامیت از `main` جلوتر بود. آن کامیت پاسخ اجرای دستی تحلیل را اصلاح می‌کند. فرانت برای سازگاری پاسخ این درخواست را مبنا قرار نمی‌دهد و نتیجه تحلیل را با گرفتن مجدد جزئیات تیکت دریافت می‌کند، اما قبل از انتشار بهتر است شاخه بک‌اند در `main` مرج شود.
